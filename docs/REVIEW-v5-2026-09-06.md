# Review of Wu'barrk's v5 ("ValCargo-Final Build-v5.zip") — 2026-09-06

**Reviewed:** `DESIGNv5.md` (51 KB), two identical HTML renders of it (same MD5; their `<title>` still says v4),
and `norse_dwarf_merchant-resized.glb` (76 MB). No code in the zip.
**Against:** the decompiled engine (`ilspycmd`, installed `assembly_valheim.dll`, 2026-09-06), ServerSync's
`ConfigSync.cs` (master, 1415 lines), the sibling CLAUDE.md files and Ragnarok's Wrath reference docs, our v2
design of record (`docs/DESIGN.md`), and the brief.
**How:** seven independent reviewers (engine, network, house style, assets, game design, consistency with v2,
buildability on this machine), 61 raw findings merged to 56, each verified by three adversarial lenses, a
completeness critic added 9 more; 53 survived, 12 were refuted. 208 Haiku agents. I then re-read every survivor
against the sources and re-graded a few (noted where I did).

---

## 1. Verdict

v5 is our v2 with three additions: a VikingOS-style escrow trade terminal, an asset pipeline for the custom body,
and a Unity installation manual. The skeleton is sound because it is v2, often verbatim (authority partition,
active-block flight, InIntro carry, ServerSync channels, economy formulas, patches, config, dialogue, checklist).

It is **not yet the design of record**, for four reasons, in cost order:

1. **The model pipeline contradicts itself and the delivered asset.** Section 6.7 rigs a Humanoid with an animator;
   sections 6.8–6.9 build and load a static `MeshFilter` mesh with a `BoxCollider`. The GLB has no rig, no
   animation, and 1.85 million triangles. Neither path in the doc can turn that file into a walking NPC.
2. **It drops the Odin vanish**, which the brief locked (Nomadicwar #45, Thorium #46), for "fx_mist_spread and a
   horn". It also drops v2's restart sweep, pilot-disconnect handling, Valkyrie-registration fallback, message trust
   table, milestones, and risks. Those are the sections that keep a server clean when things go wrong.
3. **A handful of engine and ServerSync claims are wrong**: heartbeats that ServerSync does not send, a spline the
   Valkyrie does not fly, a 1.5 m talon release that does not exist, server validation of a client inventory that
   cannot be read.
4. **House-style breaks**: a `Priority.High` replacing prefix (the pattern the family formally retracted after it
   cost half a sibling's patch CPU), runtime material editing with no recorded exception, `net48`, and a section
   that presents inherited lessons as "MANDATORY INSTRUCTIONS" measured here.

What v5 adds that v2 should take: the escrow's nonce ring and `ExpectedPrice` field, the "no inventory mutation
before the server's answer" rule stated as a guarantee, the asset-pipeline lessons (with their real source cited),
the `AttachPoint` anchor, and the Windows/Linux dual-workstation reality it exposes.

## 2. The model, measured

| Property | Delivered | What a Valheim NPC body needs |
|---|---|---|
| Triangles / vertices | 1,854,666 / 1,000,905 | ~15k–40k triangles (vanilla humanoids are in this band) |
| Rig | none (`skins` absent, one node `mesh_node`) | Humanoid skeleton with skin weights |
| Animation clips | none | idle, walk, run-in-place, talk gesture, hang (carried), plus whatever vanilla drives |
| Textures | base colour 4096², normal 4096², metallic-roughness 2048², all JPEG, ~21 MB | 2048² (1024² is fine at NPC distance), DXT compressed at build time |
| Size | 76 MB | source only; the shipped bundle should be 5–10 MB |
| Scale | 0.94 × 1.37 × 0.49 m | right for a dwarf; keep |
| Material | double-sided PBR | single-sided, cloned Valheim creature shader (v5 §6.6 is right about this) |

The file is a Meshy sculpt passed through Blender's exporter (glTF I/O 4.4.55). It is a statue, and a heavy one.

A second file arrived later the same day, `dwarf_merchant.glb` (88 MB, generator `meshy-scene`): the raw Meshy
export the zip's file was made from. Same mesh (1,000,881 vertices, 1,854,760 triangles), same three textures,
still no rig and no clips; it is 1.90 m tall where the "resized" one is 1.37 m, and it carries tangents that the
Blender re-export dropped. **Decision (owner, 2026-09-06): the resized file is the source of truth.** Its 1.37 m
height is the intended dwarf scale; tangents are regenerated at build time anyway (v5 §6.5, `RecalculateTangents`),
so nothing is lost. It lives in `ValCargo-Final Build-v5.zip` in Downloads until the Unity project directory exists;
do not commit a 76 MB binary to the mod repo. Neither file changes the plan above.
Before any of v5's section 6 applies, it needs, in this order:

1. **Retopology or decimation** to ~30k triangles (Blender Decimate for a first pass; Instant Meshes or a manual
   retopo for a clean deform). Re-bake the 4K maps onto the low mesh at 2048².
2. **Rig.** Humanoid skeleton and skin weights (Mixamo auto-rig is the fast path; Rigify in Blender the controlled
   one). Add the `AttachPoint` empty between the shoulder blades (v5 §6.7's `(0, 1.25, -0.35)` is a good start).
3. **Clips.** Idle, walk, talk gesture, hang. Export FBX or glTF **with** skin and clips.
4. **The animator contract.** Vanilla `Character`, `Humanoid` and `MonsterAI` drive these parameters on whatever
   animator the body carries (decompiled today): floats `forward_speed`, `sideway_speed`, `turn_speed`, `tilt`,
   `statef`; bools `onGround`, `falling`, `inWater`, `encumbered`, `flying`, `sleeping`, `sitting`, `freeze`,
   `blocking`; ints `statei`; triggers `attack`, `stagger`, `alert`, `interact`, `consume`, `eat`, `jump`,
   `equip_hip`, `fly_takeoff`, `fly_land`. `ZSyncAnimation` replicates the bools, floats and ints listed on the
   prefab (`m_syncBools`, `m_syncFloats`, `m_syncInts`). A custom Animator Controller must declare at least the
   locomotion set (`forward_speed`, `sideway_speed`, `turn_speed`, `onGround`, `falling`) or the merchant slides.
5. **Unity version.** The installed Valheim runs on **Unity 6000.0.61f1** (`UnityPlayer.dll` product version and
   `globalgamemanagers`). A bundle must be built with that Editor or an older one; v5's pin is correct. This
   machine has **6000.5.4f1** only (the two Unity projects here use it), so install 6000.0.61f1 through the Hub
   before building, or build on the Linux box that already has it. The Unity CLI is present here at
   `%LOCALAPPDATA%\Unity\bin\unity.exe`.
6. **Then v5 §6.3–6.6** as written: no `-nographics`, `ENABLE_UNITY_COLLECTIONS_CHECKS`, tangents, DXT5nm swizzle,
   donor material neutralisation, `Compile Remove="Unity\**"`, the copy step. These come from
   `RagnaroksWrath/docs/reference/JOTUNN-AND-HEADLESS-AUTOMATION-FACTS.md` §7–§8 (measured in this household);
   there is no §9 there, and the "Fact 9" about the `windows-mono` module is unverified.

And the loader must change: a creature body is a `SkinnedMeshRenderer` under an `Animator`, not a `MeshFilter`;
its collider is a `CapsuleCollider` (`Character.m_collider`, decompiled), not a `BoxCollider`. v5 §6.9 swaps the
wrong components and would silently do nothing on a Dverger.

## 3. Findings that change the design

Severity is mine. Finding ids refer to the review run (`wf_2fab2464-025`).

### 3.1 Brief conformance
- **Odin vanish dropped (F03, major).** §4.3 line 130: "despawns in cloud of mist (fx_mist_spread) and plays horn
  sound". The brief and v2 §3.6 use `Odin.m_despawn` (a public `EffectList` on the `odin` prefab, whatever prefabs
  it holds). Restore it; keep the horn as an extra sound if wanted, but say it is departure audio, not the earned
  summon horn (C02).
- **Scope statement missing (C02, C07 in part).** v5 calls itself definitive but never says what 0.1 ships. Per the
  brief: rested + comfort gate, buys AND sells, barter, live prices, shared visuals, ServerSync are all 0.1; the
  earned horn and the custom body are later. (The critic's claim that "sells" and "comfort" are deferred came from
  the superseded v1 plan; ignore that part.)

### 3.2 Engine claims
- **Flight geometry (F13, F14, F31, major).** No cubic Hermite spline: `Valkyrie.UpdateValkyrie` flies three
  waypoints with linear steps and a banked turn. No release at 1.5 m: `m_dropHeight = 10` is ground clearance the
  whole way, and the drop fires on XZ proximity (0.5 m). No vertical climb: the fly-away point is a lateral
  waypoint at altitude. Describe what the code does; v2 §3.2 already does.
- **Talon "IK" (F41, minor).** Vanilla attaches by transform assignment (`SyncPlayer`), no IK. Our pin does the same.
- **Confirmed correct (F42, F45):** the `InIntro` mechanism and the "server writes to a client-owned ZDO are lost"
  invariant. Keep.

### 3.3 Networking and ServerSync
- **Heartbeats (F02, F26, major).** "VisitState every 1–2 s" and "MarketState on a 15 s heartbeat" do not exist:
  `CustomSyncedValue` broadcasts on change (`ConfigSync.cs` ~227–232), nothing ticks. Also ~1.2 KB is under the
  10 000-byte compression floor, so "Deflated" is wrong too. State: on change, uncompressed, versioned string.
- **Server validation of "player inventory capacity" (F15, major).** The server cannot read a client-owned ZDO
  reliably (v2 §1). Server validates nonce, stock, price conformity, purse; the client's inventory is trusted after
  the answer, as vanilla trusts it always. Say exactly that.
- **Keep (F50, F51, F44):** the 500-entry nonce ring (defence in depth; direct sockets do not stop a replayed
  packet), `ExpectedPrice` in the request so a price tick rejects cleanly, and "no local mutation before the
  server's answer". These go into v2's Deal.

### 3.4 House style
- **`StoreGui.Show` prefix at `Priority.High` with `__runOriginal=false` (F18, F47, major).** The retracted pattern
  (Ragnarok's Wrath rule 1, Undertow). If a custom terminal stays, it is a `Priority.Low` prefix that skips vanilla
  only when the trader is Ingvar's proxy, recorded as a locked decision with its reason. v2 chose to extend the
  vanilla panel instead; that choice is the partners' (section 5).
- **Runtime material editing (F46, minor→decision).** §6.6/§6.9 clone and edit a creature material at runtime.
  Undertow's widened rule 4 bans touching materials and shaders; the intent was environmental surfaces, and a cloned
  instance on our own object is arguably outside it. Either record the exception or move the whole material setup
  to build time (the bundle carries a finished material).
- **Provenance (F17, minor).** §6 frames inherited lessons as "MANDATORY INSTRUCTIONS FOR ANY AI AGENT" and cites a
  §9 that does not exist. Cite `JOTUNN-AND-HEADLESS-AUTOMATION-FACTS.md` §7–§8 and AwayFromHome by name, drop the
  imperative frame (Undertow: inherit, do not write up as if measured here).
- **`net48`, `AllowUnsafeBlocks true`, `libs-Tools` paths (F35, minor).** House is `net472`, unsafe off, `libs\`
  from `fetch-libs.ps1`, ILRepack target as v2 §8 shows.
- **Personal Linux paths (F34, C05, F27, minor).** `/home/rohan/…` throughout §6.1–6.2 and no Windows method.
  This repo's owner is on Windows; add Method C: `& "C:\Program Files\Unity\Hub\Editor\6000.0.61f1\Editor\Unity.exe"
  -batchmode -quit -projectPath <p> -executeMethod MerchantBundleBuilder.BuildKit -logFile <log>` (no `-nographics`,
  no xvfb), and placeholders for the Linux side.

### 3.5 What v5 lost from v2 (all major as a set)
Boot-time orphan sweep (F23, C04); pilot disconnect mid-flight and mid-visit (F24); Valkyrie prefab registration
risk and the pilot-instantiates fallback (F25); the iterative active-block clamp (F22); the Deal primitive (F20);
the `UpdateBuyButton`/`UpdateSellButton` patches (F21); the message trust table (F36, C03); milestones with proofs
(F39); risks (F40); the `Valkyrie.Awake` rationale about `m_instance` (F48); admin command gating for `cargo visit`
via RavenEye's `AdminGate` shape (C06); sidecar format versioning as Cairn does it (C10). v2 has each; a merge
restores them.

### 3.6 Refuted, and why it matters
Twelve findings were killed by the verifiers, and rightly: the 76 MB file is source, not the shipped bundle (F07);
tangent recalculation on a glTFast mesh is correct because glTFast imports none (F08, F28); the csproj removals and
ILRepack are documented (F10, F11, F56); the 90 m start is a deliberate override of vanilla's 500 m, not a
misreading (F12); the nonce ring is not overkill (F43). One refutation I overrule in part: F16, the staging-tray
**auto-tear-down on price ticks**. It is not a brief violation, but with three players at the merchant every deal
by one dissolves the others' staged trades. `ExpectedPrice` already rejects a stale deal; a "price changed, confirm
again" prompt keeps correctness without the griefing lever. Design choice for the partners.

## 5. Decisions only the partners can make
1. **Animated body or statue for 0.1?** The brief says he walks and calls out. That means a rigged body: who does
   the retopo and rig, and when. Until then, the Dverger placeholder stands (v2 §3.3).
2. **Custom Black-Gold terminal or the vanilla store extended?** House precedent says extend; v5's escrow UX wants
   a dual-pane tray. Either is buildable; the custom one needs a recorded exception and the Low-priority guard.
3. **Tear-down on price tick, or reject-and-reconfirm?** (§3.6.)
4. **Where bundles get built**: install 6000.0.61f1 here, or Wu'barrk's Linux box builds and commits the bundle.
5. **Materials at runtime**: record the exception, or bake at build time.
6. **Restart mid-visit**: resume the remaining time (v2) or restart the clock.
